# server (Magav.Server) — scoped context

.NET business logic (depends on `common`): the SMS scheduler subsystem, JWT auth, repositories, `DbInitializer`. Full detail → `.ai/docs/components/server.md`.

## Critical to know
- **DayGroup = the day the SMS is SENT (run day), not the shift's day** (holiday-aware ladder Sat→Fri→SunThu); `DaysBeforeShift` is the look-ahead (`Services/Sms/SmsSchedulerService.cs`). `WeekdayAdvance` **and `AdminAdvance`** (`SmsSchedulerService.cs:117`) share one half-open `[today+N, NextWorkingDay(today)+N)` window and derive `{תאריך}`/`{יום}` per-shift — which is why the seeded `AdminAdvance` config is pinned to `SunThu` / `DaysBeforeShift=1`.
- **Same-day reminders APPEND the location; Advance/WeekdayAdvance/Manual do NOT. `AdminAdvance` and every one-shot admin send append BOTH the mission block and the vehicle block** (`SmsReminderService.BuildAdminSmsBlocks`).
- **Shift-type isolation is per-query.** `ShiftsRepository.GetByDateAsync` carrying `ShiftType='Operational'` is the choke point (by-date page, delete-group and update-group all load through it); `GetDatesWithShiftsAsync`/`GetDatesWithUnresolvedAsync`/`GetCanceledByMonthAsync`/`HasSameDaySmsBeenSentAsync` each carry it independently; **the Excel import's range-delete carries it as a P0 data-loss guard** (`ShiftsImportService.cs:110-113`). Deliberately type-agnostic (marked in-comment — do NOT add a predicate): `GetByVolunteerIdAsync`, `GetByIdAsync`, and the monthly cleanup. Admin groups key on `(ShiftDate, ShiftTime, Description)` with `ShiftName == Description`.
- **Administrative template ids are resolved BY NAME** (`ORDER BY Id LIMIT 1` — `Name` is not unique) and stored in `AppSettings`; the startup chain is ORDER-DEPENDENT (templates → config → settings) and **skips + logs** rather than writing a dangling reference. Renaming an admin template breaks that chain silently, and the delete guard does not protect those two templates. [ISS-011]
- **Two-tier SMS dedup:** `SmsLog` (ShiftId, ReminderType) NOT-EXISTS check + `SchedulerRunLog` UNIQUE(ConfigId, TargetDate, ReminderType). `Database/Repositories/SchedulerRunLogRepository.cs` now swallows **only** the UNIQUE violation as a dedup hit; any other DB error is logged distinctly and returns null **without rethrowing** (a rethrow would re-run the batch → duplicate SMS) — kept structurally identical to the Android mirror. [ISS-006 resolved]
- **`SmsSchedulerService` (singleton `BackgroundService`, polls 60s) resolves scoped services via `IServiceScopeFactory.CreateScope()`.**
- **Auth:** access token 15min, refresh token 7 days stored as SHA256 (rotated on refresh), lockout after 5 fails/15min (`Services/AuthService.cs`). The refresh-token TTL (7d) intentionally diverges from the Android mirror (3d) — an accepted divergence (`tools/parity.md` #1). [ISS-004]
- **Password policy lives inline in `change-password`** (≥6 + letter + digit) — the old unused `Helpers/PasswordValidator.cs` was deleted in `2989b01`; do not reintroduce a second validator. [ISS-009 resolved]
- **Seeding runs ONLY on a fresh DB** — new seed rows don't reach existing installs (`Services/DbInitializer.cs`). Add a new default as a **separate, unconditional, idempotent migration** placed outside the `if (!dbExists)` branch (`INSERT OR IGNORE` / insert-if-name-absent), as `WeekdayAdvance`, the 3 admin templates, the `AdminAdvance` config and the `AppSettings` keys all are. Those AppSettings keys are seeded **once-only**, so a key pointing at a deleted template never self-heals.
- **The .NET SMS send path was NOT given the Android at-most-once rewrite** — it still logs post-send and dedups on `Status='Success'` only, so it retains the failure mode behind the 2026-08 duplicate-SMS incident. Accepted divergence (`tools/parity.md`); port the write-ahead scheme before this target ever sends real SMS. [ADR-024]
- Active-shift queries MUST filter `IsCanceled = 0` (soft-cancel).
