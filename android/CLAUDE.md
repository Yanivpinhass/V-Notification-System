# android — scoped context

Kotlin hybrid app (source in `app/src/main/`): embeds a Ktor HTTP server (localhost:5015) in a foreground service that mirrors the .NET API, with a WebView loading the same React build; SMS sent natively via `SmsManager`. Room + SQLCipher, Koin DI, AlarmManager + WorkManager. Full detail → `.ai/docs/components/android.md`.

## 🚨 Room schema changes can SILENTLY WIPE ALL USER DATA
Any `@Entity` change requires, every time: (1) bump `@Database(version=N)` in `app/src/main/java/com/magav/app/db/MagavDatabase.kt` (currently **11**); (2) add `MIGRATION_N_(N+1)` (idempotent SQL); (3) register it in **BOTH** `addMigrations(...)` sites in `MagavApplication.kt:109,135` (initial build AND recovery rebuild); (4) make the migration's resulting schema match the entity exactly (every index + every `@ColumnInfo(defaultValue=…)`). Latest examples done correctly: **`MIGRATION_9_10`** (5 admin columns on `Shifts`) and **`MIGRATION_10_11`** (`Locations.LocationType` + `Shifts.VehicleLocationId`) — both **pure `ALTER TABLE ADD COLUMN`**. Keeping them additive is exactly why those columns have **no index and no `@ForeignKey`**: either would change the `CREATE TABLE` shape and force a table rebuild. A NOT-NULL column can be added only *with* a DEFAULT (which backfills existing rows to `'Operational'`/`'Vehicle'`), and it must byte-match the entity's `defaultValue`. Note that widening an existing column's VALUE set needs no migration at all — `SmsStatuses.Dispatched` was added to the plain TEXT `Status` column with `@Database` untouched. `initializeDatabase()` (`MagavApplication.kt:102-137`) deliberately omits `fallbackToDestructiveMigration` and recovers ONLY on SQLCipher key/corruption errors — every other error (incl. a forgotten-migration schema-hash mismatch) is re-thrown so it crashes VISIBLY. **Verify on a populated dev device before shipping.** [ADR-004 — born from a real data-loss incident]

## Critical to know
- **Bump `versionCode`** in `app/build.gradle.kts` (currently **84** / 1.5.1) before EVERY APK build — the WebView caches the PWA service worker; `MainActivity.clearCacheOnVersionChange()` clears it only on a version-code bump. Forgetting = users stuck on old UI.
- **License expiry is compiled in — currently `2027-06-01`** (`LICENSE_EXPIRY_DATE` default, `app/build.gradle.kts:21-22`). After that date `LicenseValidator.isValid()` fails at UI launch and the user sees only a generic "שגיאה בהפעלת המערכת" page. Fix = rebuilt APK installed before the date (last extended in `719e71a`).
- **Auto-callback-to-gate** (`callback/` package — `CallbackLogic` + `CallbackPhoneStateReceiver` + `CallbackAlarmReceiver`). Eligible unanswered incoming call → reject + auto-dial the Gate after 20s. Detection = manifest `PHONE_STATE` + `READ_CALL_LOG`; the 20s wait = ONE one-shot `setExactAndAllowWhileIdle` alarm (reuses the `AlarmScheduler`/`SmsAlarmReceiver` pattern); reject/dial via `TelecomManager.endCall()`/`placeCall()` (perms `CALL_PHONE`+`ANSWER_PHONE_CALLS`+`READ_CALL_LOG`, added to `MainActivity.requestPermissions()`). Correctness rests on ONE fire-time `callState==RINGING` re-check; the fire receiver is `exported=false`. Config = `CallbackConfig` Room singleton + the Android-only `GET/PUT /api/callback-config` (`CallbackConfigRoutes.kt`). Fully decoupled from SMS — touches no SMS file / `MagavServerService`. [ADR-021]
- **Device-allowlist gate (fail-CLOSED).** At WebView launch, after the license gate, `DeviceAllowlist.isAllowed()` admits a device only if its `Settings.Secure.ANDROID_ID` is in the hardcoded `license/DeviceAllowlist.kt` set; else a Hebrew block page (with a `NativeClip.copyDeviceId()` copy button) — never the app (`MainActivity.kt:191-194`). **An EMPTY set blocks EVERY device** (opposite of `LicenseValidator`'s fail-open), and ANDROID_ID is **keystore-scoped** → regenerating the debug keystore / building on another machine / release signing invalidates the list and locks everyone out. Build the distributed APK on ONE machine + back up the keystore. [ADR-020]
- **Constants must mirror .NET `MagavConstants` exactly** — `util/Constants.kt` (6 ReminderTypes incl. `WeekdayAdvance`/`AdminAdvance`, SmsStatuses incl. `Dispatched`, DayGroups). Verified in sync (`node tools/parity-lint.mjs`).
- **Scheduler (v1.5.0 duplicate-SMS fix):** exact `AlarmManager` alarms in **Israel tz** per enabled `SchedulerConfig`/day-group → `SmsAlarmReceiver` → `SmsSchedulerWorker` (WorkManager; retry cap = initial + 1 executing retry; guarded per-worker `setForeground`) → query eligible shifts (filter `IsCanceled=0`), check approval+phone, then **WRITE-AHEAD dedup**: any (ShiftId, ReminderType) `SmsLog` row of ANY status blocks re-dispatch; the row is INSERTed as `Dispatched` BEFORE `AndroidSmsProvider` sends (Mutex-serialized, **60s** sent-broadcast wait, all multipart parts tracked, tri-state `Outcome` CONFIRMED/FAILED/UNKNOWN) and updated after. Batch executions serialized by a process-global mutex in `SmsReminderService`. An end-of-run duplicate detector (run-bounded, non-Fail rows) alerts on `magav_error_channel`. `BootReceiver` re-schedules on boot. See `Plans/duplicate-sms-fix-implementation-plan.md`.
- **`VolunteerEntity` intentionally diverges from the .NET `Volunteer` model** — it keys on a unique `MappingName` and deliberately OMITS `InternalIdHash`/`FirstName`/`LastName`/`RoleId` (the .NET hashed-id SMS-approval flow is .NET+React only; Android never reads those columns). Accepted by design — do NOT add columns for parity (that's a Room `@Entity` change → the data-wipe hazard above). See the file-header comment in `db/entity/VolunteerEntity.kt`, ADR-016, `tools/parity.md`. [ISS-003 accepted]
- **Shift-type isolation (`ShiftType` = Operational | Administrative) is per-query in `db/dao/ShiftDao.kt`.** Operational routes call `getByDateRangeAndType(..., "Operational")`; every operational *group* query carries `ShiftType = 'Operational'`; the import range-delete carries it as a **P0 data-loss guard**. **Four queries are deliberately type-agnostic and each says so in-comment — do NOT add a predicate:** `getByDateRange` (its only caller is auto-callback eligibility), `getByVolunteerId` (delete cascade), `cancelById`, `deleteOlderThan` (monthly cleanup). Admin group ops key on `(date, ShiftTime, Description)` and keep `ShiftName == Description`. [ADR-022]
- **Administrative endpoints are NOT an Android-only carve-out** — `api/routes/AdminShiftRoutes.kt` + `AdminSchedulerRoutes.kt` mirror real .NET endpoints, so a change there must be applied to `Program.cs` and the React services too. (The Android-only ones remain `/api/settings/sms-sim` and `/api/callback-config`.)
- Secrets (DB passphrase, JWT key) in EncryptedSharedPreferences; SIM choice in the `AppSettings` table (`sms_sim_subscription_id`, -1 = default). Admin template-role ids live in the same table (`admin_assignment_template_id` / `admin_today_template_id`, resolved BY NAME at seed time). Seeded admin password `12345`.
- `db/dao/AiQueryDtos.kt` is orphan/dead code. Largest files: `api/routes/ShiftRoutes.kt` (923), `db/DatabaseInitializer.kt` (486), `api/routes/AdminShiftRoutes.kt` (466), `service/SmsReminderService.kt` (402), `scheduler/SmsSchedulerWorker.kt` (375).
