# Magav V-Notification-System — Agent Context

Hebrew RTL volunteer-shift management + SMS-reminder system for patrol ("ניידת") coordination. Manages volunteers, Excel-imported shifts, and scheduled SMS reminders, with Hebrew/RTL admin tooling. **Two deployment targets share ONE React frontend:** (1) **Web** — .NET 8 Minimal API + React SPA on Ubuntu (Nginx/systemd); (2) **Android** — Kotlin app embedding a Ktor server + WebView (same React build), sending SMS natively via `SmsManager`.

## Architecture
Hybrid, layered. Web backend = .NET project chain `Magav.Common → Magav.Server → Magav.Api` (acyclic). React SPA served by the API and by the Android WebView. Android = embedded Ktor server (localhost:5015) mirroring the .NET API surface. Components map to `.ai/docs/components/`.

## Components (5)
- **common** — shared .NET lib: Models, the custom `DbHelper`/NPoco ORM wrapper, `MagavConstants`, Excel, encryption. → `.ai/docs/components/common.md`
- **server** — .NET business logic: SMS scheduler subsystem, JWT auth, repositories, `DbInitializer`. → `.ai/docs/components/server.md`
- **api** — .NET 8 Minimal-API entry: all endpoints + DI + middleware live in one `Program.cs`. → `.ai/docs/components/api.md`
- **web-client** — React 18 + TS + Vite SPA (Tailwind/Shadcn, RHF+Zod, PWA); shared by web + Android. → `.ai/docs/components/web-client.md`
- **android** — Kotlin: Ktor + Room/SQLCipher + AlarmManager/WorkManager + native SMS. → `.ai/docs/components/android.md`

## Critical to know (non-obvious, load-bearing)
- **The same REST contract + domain model is implemented THREE times with no shared code and no tests** — .NET `web/server/Magav.Api/Program.cs`, Android Ktor `android/.../api/routes/*`, consumed by React `web/client/src/services/*` (entities triplicated: .NET Models / Room entities / TS types). A contract or rule change must be applied to ALL THREE or it silently drifts. **Accepted by design** (dual-target architecture). Accepted divergences (refresh-token TTL 7d .NET vs 3d Android; password policy; the Volunteer entity below; the Android-only endpoints; and the SMS-dedup semantics below) live in `tools/parity.md` — run `node tools/parity-lint.mjs` before shipping a value-set change. The lint now covers **5** value-sets: `ReminderTypes`/`SmsStatuses`/`DayGroups`/`ShiftTypes`/`LocationTypes`. It does NOT cover endpoint or DTO shapes, nor the `AppSettingsKeys` literals — those are hand-mirrored. [ISS-004]
- **Room schema changes can SILENTLY WIPE ALL USER DATA if done wrong.** Any `@Entity` change requires: bump `@Database(version=N)` in `android/.../db/MagavDatabase.kt` (currently **11**), add `MIGRATION_N_(N+1)`, and register it in BOTH `addMigrations(...)` sites in `MagavApplication.kt:109,135`. Latest: `MIGRATION_9_10` + `MIGRATION_10_11` (the admin/location columns) — both **pure `ALTER TABLE ADD COLUMN`**. Keeping them additive is why the new columns deliberately have **no index and no `@ForeignKey`**: either would change the `CREATE TABLE` shape Room hashes → table rebuild → the hazard. A NOT-NULL column can be added only *with* a DEFAULT (which backfills existing rows), and that default must byte-match the `@ColumnInfo(defaultValue=…)`. `initializeDatabase()` (`android/.../MagavApplication.kt:102-137`) deliberately omits `fallbackToDestructiveMigration` and recovers ONLY on SQLCipher key/corruption errors — every other error (incl. a forgotten-migration schema-hash mismatch) is re-thrown so it crashes VISIBLY instead of wiping data. **Verify on a populated dev device before shipping.** [ADR-004 — born from a real data-loss incident]
- **Two shift types + two location types (2026-07-14).** `Shifts.ShiftType` = `Operational` | `Administrative`; `Locations.LocationType` = `Vehicle` (מיקומי ניידות) | `General` (mission locations). Both default to the pre-existing meaning, so old rows and old callers are unaffected. **Isolation is per-query, not global** — every operational read/group-op must carry `ShiftType = 'Operational'` (the same class of easy-to-forget filter as `IsCanceled = 0`), while four paths are deliberately type-agnostic and say so in-comment: by-id reads/cancels, the volunteer-delete cascade, the monthly cleanup, and Android's auto-callback eligibility read. The Excel import's range-delete carries the predicate as a **P0 data-loss guard**. Admin groups key on `(ShiftDate, ShiftTime, Description)` — NOT the operational `(ShiftDate, ShiftName, CarId)` — and `ShiftName` is written == `Description` (NOT NULL), so an admin group can collide with an operational team name if a predicate is missing. [ADR-022/ADR-023]
- **DayGroup = the day the SMS is SENT (run day), not the shift's day**; `DaysBeforeShift` is the look-ahead. Holiday-aware ladder (Sat → today/tomorrow-is-holiday → Fri → SunThu). `web/server/Magav.Server/Services/Sms/SmsSchedulerService.cs:104-127`; mirrored `android/.../scheduler/SmsSchedulerWorker.kt:363-374`. Easy to get backwards.
- **Same-day reminders APPEND the location** (city/name + Waze link) after the template; **Advance / WeekdayAdvance / Manual do NOT** (location may change before the shift). Changing a location after the same-day SMS went out triggers a `LocationUpdate` re-notify.
- **SMS dedup — ANDROID is write-ahead + any-row-blocks (v1.5.0, duplicate-SMS fix):** the Android scheduler INSERTs the `SmsLog` row with status `Dispatched` BEFORE handing the SMS to the radio (fail-closed: no row ⇒ no dispatch), updates it to Success/Fail after, and dedups on ANY existing (ShiftId, ReminderType) row regardless of status — at-most-once automatic dispatch; even Fail rows are only retried manually. A process-global mutex serializes batch executions; WorkManager retries are capped (initial + 1). See `Plans/duplicate-sms-fix-implementation-plan.md`. A timeout means UNKNOWN, not failure — it is logged `Dispatched`, counted as sent, and never surfaced as a red error (a red toast for a delivered message is what drove operators to re-send from the phone's Messages app). **.NET still uses the OLD scheme** (post-send logging, Success-only dedup) — accepted divergence until the web target ships, so the web target still carries the pre-incident failure mode. `SchedulerRunLog` remains bookkeeping on both platforms, never a gate. [ADR-024]
- **Soft-cancel:** cancelling sets `IsCanceled=1` + `CanceledAt` (never deletes). **EVERY query listing active shifts MUST filter `IsCanceled = 0`** (eligibility, by-range, available-dates…). Hard-delete only via the canceled-shifts page after soft-cancel.
- **6 ReminderTypes:** `SameDay, Advance, WeekdayAdvance, LocationUpdate, Manual, AdminAdvance` (`web/server/Magav.Common/MagavConstants.cs`). `WeekdayAdvance` uses a half-open `[today+N, NextWorkingDay(today)+N)` window to pull weekend/holiday advance-sends onto a working day (`SmsSchedulerService.cs:117`); **`AdminAdvance` reuses that window verbatim**, which is why its config is pinned to `SunThu` / `DaysBeforeShift=1` (the only N for which the window is gap/overlap-free) and ships disabled. **`MagavConstants` is canonical; Android `util/Constants.kt` MUST mirror it exactly** — verified in sync across all 5 value-sets; run `node tools/parity-lint.mjs`.
- **Administrative message templates are resolved BY NAME, and their ids live in `AppSettings`** (`admin_assignment_template_id` / `admin_today_template_id`) — never hardcoded, because an upgraded DB may already have used ids 4/5. `MessageTemplate.Name` is not unique, so lookups are `ORDER BY Id LIMIT 1`; a failed lookup SKIPS the dependent seed and only logs. Two consequences: **renaming an admin template breaks the startup seed chain silently**, and the template-delete guard (which only checks `SchedulerConfig` references) does **not** protect these two — deleting one leaves a dangling key that never self-heals [ISS-011].
- **`user.roles` is a string ARRAY** (`["Admin"]`), NOT `user.role` — always `roles.includes("Admin")`. Roles: `Admin`, `SystemManager`, `User`. localStorage keys: `accessToken`, `refreshToken`, `user`.
- **Bump `versionCode`** in `android/app/build.gradle.kts` (currently **84** / 1.5.1) before EVERY APK build — the WebView caches the PWA service worker; `MainActivity.clearCacheOnVersionChange()` clears it on a version bump. Forgetting = users stuck on the old UI.
- **Android has a compiled-in license expiry (a time-bomb) — currently `2027-06-01`.** `LICENSE_EXPIRY_DATE` is a `buildConfigField` default in `android/app/build.gradle.kts:21-22`; `LicenseValidator.isValid()` returns false once today (Israel tz) is AFTER that date (or the date fails to parse), and `MainActivity` (checked at UI launch, `MainActivity.kt:218`) then shows only a generic "שגיאה בהפעלת המערכת" page — nothing on screen says "license". The only fix is a rebuilt APK installed on the device, so extend the date and ship BEFORE it passes (last extended `2026-10-06` → `2027-06-01` in `719e71a`, two days before expiry).
- **Android is gated to an explicit device allowlist (fail-CLOSED).** At WebView launch `MainActivity` checks `DeviceAllowlist.isAllowed()` — a hardcoded set of `Settings.Secure.ANDROID_ID`s — AFTER the license gate; a non-listed device gets a Hebrew block page (with a `NativeClip.copyDeviceId()` bridge to copy its id), never the app (`MainActivity.kt:191-194`). **An EMPTY set blocks EVERY device** (the OPPOSITE of `LicenseValidator`, which fails open). ANDROID_ID is scoped to the APK signing keystore, so regenerating the debug keystore, building on another machine, or switching to release signing **invalidates the whole list and locks everyone out**. Add approved ids in `android/.../license/DeviceAllowlist.kt`; always build the distributed APK on the same machine + back up the keystore. [5124870]
- **Auto-callback-to-gate (Android-only, `android/.../callback/`).** An eligible unanswered incoming call (volunteer on a today/yesterday non-canceled shift, feature active, inside the Israel-tz window) is rejected and the configured Gate number auto-dialed after 20s. Detection = manifest `PHONE_STATE` + `READ_CALL_LOG` (NOT `CallScreeningService`); the 20s wait = a SINGLE one-shot `setExactAndAllowWhileIdle` alarm; reject/dial via `TelecomManager.endCall()`/`placeCall()` (needs `CALL_PHONE`+`ANSWER_PHONE_CALLS`, NOT `ACTION_CALL`). Correctness rests on ONE fire-time `callState==RINGING` re-check (no state machine); busy line ⇒ do nothing. The **All callers** toggle bypasses the volunteer filter (any caller); Active + window still apply. Config is the `CallbackConfig` singleton + the **Android-Ktor-only** `GET/PUT /api/callback-config` (no .NET counterpart — another accepted [ISS-004] divergence, like `/api/settings/sms-sim`); the React `CallbackSettingsPage` is gated to the Android WebView via `window.NativeMedia`. Decoupled from SMS — touches no SMS file or `MagavServerService`. [ADR-021]
- **Seeding runs ONLY on a fresh DB** — new seed rows do NOT reach existing installs (`DbInitializer.cs` / Android `DatabaseInitializer.kt`). A new default row must be added as a **separate, unconditional, idempotent migration** (`INSERT OR IGNORE` / insert-if-name-absent) that runs outside the fresh-DB branch — as `WeekdayAdvance`, the 3 admin templates, the `AdminAdvance` config and the `AppSettings` keys all are. Related trap: when seeding a NEW key into an EXISTING key-value table, guard **per key**, not with a method-level early return (an upgraded install already has `sms_sim_subscription_id`, which would otherwise skip everything after it).
- **RTL gotchas:** dialog close (X) is on the LEFT (`left-4`); `Switch` needs `dir="ltr"` to stop transform-mirroring (`components/ui/switch.tsx`); Android WebView does NOT move `position:fixed` for the keyboard, so dialogs are TOP-aligned + scrollable — do not rely on `dvh`/`visualViewport`/bottom-sheets (`components/ui/dialog.tsx`).
- **`DbHelper` method names differ from NPoco defaults:** `FetchAllAsync()` (all rows, no-arg), `FetchAsync<T>(expr | sql,args)`, `ExecuteQueryAsync` (NOT `ExecuteAsync`), `ExecuteScalarAsync<T>`, `SingleOrDefaultByIdAsync` (`web/server/Magav.Common/Database/DbHelper.cs`). `DbHelper` appears vendored from another codebase ("Avidov.Common") — treat as a library, not first-party.
- **Timezone is Israel / Asia-Jerusalem everywhere** (scheduling, dates, holidays).

## Security (the project's "Security First" mandate)
- Parameterized queries only (`@0,@1…` .NET; Room `@Query` params) — never concatenate SQL.
- Every endpoint `.RequireAuthorization()` unless intentionally public. The ONLY public endpoints: `POST /api/auth/login`, `POST /api/auth/refresh`, `GET /api/health`, `POST /api/public/sms-approval/{accessKey}/*` (access-key + rate-limited 3/5min). Authorization audit is currently clean.
- Use `Results.Json(ApiResponse<T>.Fail("<Hebrew>"))`, never `Results.Problem` (can leak detail in dev) — now followed everywhere (the login/refresh/logout/import deviations were converted in `2989b01`). Never expose exception detail; full details server-side only.
- File uploads: CSRF `X-Requested-With` header + `.xlsx/.xls` ext + magic-byte check (`0x50 0x4B` / `0xD0 0xCF`) + in-memory, max 10MB.
- Validate all inputs server-side even if validated client-side.

## Git workflow
- **Never commit or push on your own — only when I explicitly ask.** After making changes, stop and leave them uncommitted in the working tree; do not commit or push proactively, and do not nudge to commit.
- **Default commit/push target is `main`.** When asked to "commit", "push", or "commit and push" without naming a branch, work directly on `main` and push to `origin/main` — do NOT create or switch to a feature branch first. This deliberately overrides the usual "branch first when on the default branch" default. Use a different branch ONLY when explicitly asked.

## After implementing changes
- **When an implementation is finished, ALWAYS build the Android APK and report its path.** Bump `versionCode` in `android/app/build.gradle.kts` first (managed region — forgetting it strands users on the cached old UI), run `build-apk.bat`, then state the full path to the built APK (`android/app/build/outputs/apk/debug/app-debug.apk`). Applies to any code change that affects the app (the Android APK embeds the shared React build).

## Build & run (quick reference)
- **Web client** (`web/client/`): `npm install` · `npm run dev` (→ http://localhost:8080, proxies `/api/*` → :5015) · `npm run build` · `npm run lint`
- **Web server** (`web/server/Magav.Api/`): `dotnet build` · `dotnet run` (→ http://localhost:5015). Both must run together for web dev.
- **Android**: `build-apk.bat` (builds React → copies `dist/` to `android/app/src/main/assets/web/` → `gradlew assembleDebug`). Install: `adb install -r android/app/build/outputs/apk/debug/app-debug.apk`. **Bump `versionCode` first** (see managed region).
- **Publish (Linux)**: `dotnet publish -c Release -r linux-x64 --self-contained false`; deploy to `/opt/magav/` (systemd `magav.service`, Nginx). DB reset = delete `/opt/magav/db/magav.db` + restart.
